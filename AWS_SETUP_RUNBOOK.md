# uDeets AWS Multi-Account Setup Runbook

End-state goal: three AWS accounts under one AWS Organization, accessed via IAM Identity Center single sign-on. Existing dev account preserved; production account fresh and empty.

## Final account layout

```
AWS Organization (owned by udeets.app@gmail.com)
  ├── Management account       udeets.app@gmail.com   — Organizations, SSO, billing only. No workloads.
  ├── udeets-dev (member)      udeets.dev@gmail.com   — Existing account. VPC, RDS, S3, Cognito stay here.
  └── udeets-prod (member)     udeets.prod@gmail.com  — Empty, for production buildout later.
```

## Prerequisites

Before starting, you need:

- [ ] Phone number for Gmail verification (Google blocks VOIP — use a real mobile number)
- [ ] Password manager (1Password, Bitwarden) for storing root credentials of three accounts
- [ ] Authenticator app (Google Authenticator, Authy, or YubiKey) for MFA on three accounts
- [ ] Credit card for AWS management account billing (dev and prod charges will consolidate here)
- [ ] Access to `udeets.dev@gmail.com` Gmail (the existing account owner email)
- [ ] Root password for the existing `udeets.dev@gmail.com` AWS account
- [ ] ~2–3 hours of uninterrupted time

## Phase 1 — Create new Gmail accounts (~20 min)

### Task 1.1: Create `udeets.app@gmail.com`

- [ ] Go to https://accounts.google.com/signup
- [ ] First name: `uDeets`, Last name: `App`
- [ ] Username: `udeets.app`
- [ ] Set a strong password (24+ chars, generated by password manager)
- [ ] Complete phone verification with a real mobile number
- [ ] Save password to password manager
- [ ] After account creation, immediately enable 2-Step Verification:
  - Go to https://myaccount.google.com/security
  - Click "2-Step Verification" → set up with authenticator app
  - Save backup codes to password manager
- [ ] Confirm you can log in fresh in a private browser window

### Task 1.2: Create `udeets.prod@gmail.com`

- [ ] Repeat Task 1.1 with username `udeets.prod`, name `uDeets Prod`
- [ ] Enable 2FA, save backup codes
- [ ] Confirm fresh login works

## Phase 2 — Create AWS management account (~15 min)

### Task 2.1: Sign up for new AWS account

- [ ] Open a private/incognito browser window (so you don't conflict with your existing AWS session)
- [ ] Go to https://aws.amazon.com → "Create an AWS Account"
- [ ] Root user email: `udeets.app@gmail.com`
- [ ] AWS account name: `udeets-management`
- [ ] Confirm email via the verification link sent to `udeets.app@gmail.com`
- [ ] Set root password (32+ chars, generated, saved to password manager)
- [ ] Personal or Business: Business
- [ ] Full name, company name, phone, address: fill in real details
- [ ] Add credit card for billing
- [ ] Phone PIN verification
- [ ] Select "Basic Support — Free" plan
- [ ] Wait for account activation email (usually instant, can take up to 24 hrs)

### Task 2.2: Harden the management account root user

- [ ] Sign into the new management account as root
- [ ] Top right → account name → Security credentials
- [ ] Assign MFA device → use authenticator app
- [ ] Save MFA backup codes / secret to password manager
- [ ] Sign out, sign back in with root + MFA to confirm it works

### Task 2.3: Set up billing alarms in management account

- [ ] Billing and Cost Management → Budgets → Create budget
- [ ] Use a template → "Zero spend budget" → email yourself at any spend over $1
- [ ] Create a second budget → "Monthly cost budget" → set threshold to $100, alert at 50%, 80%, 100%
- [ ] Enable Cost Explorer (Cost Management → Cost Explorer → "Launch Cost Explorer" — takes 24h to populate)

### Task 2.4: Note management account details

- [ ] Capture and save: account ID (12-digit number, top right), root email, root password location in password manager, MFA device name

## Phase 3 — Enable AWS Organizations (~5 min)

Logged into the management account (`udeets.app@gmail.com`), as root.

### Task 3.1: Enable Organizations

- [ ] Search "Organizations" in top search bar → open the service
- [ ] Click "Create an organization"
- [ ] Choose "All features" (NOT consolidated billing only)
- [ ] Wait for confirmation (~10 seconds)

### Task 3.2: Create OUs (Organizational Units)

- [ ] Organizations → AWS accounts → click "Root"
- [ ] Actions → Create new → New organizational unit
- [ ] Name: `Workloads-Dev` → Create
- [ ] Repeat → name: `Workloads-Prod` → Create

---

## Phase 4 — Invite existing dev account into the organization (~10 min)

Continue in management account.

### Task 4.1: Send invitation

- [ ] AWS Organizations → AWS accounts → "Add an AWS account"
- [ ] Choose "Invite an existing AWS account"
- [ ] Email or account ID of account: `udeets.dev@gmail.com`
- [ ] (Optional) Add a note: "Joining udeets organization as dev environment"
- [ ] Send invitation

### Task 4.2: Accept invitation in existing dev account

- [ ] Open a different browser (or sign out of management) → sign into `udeets.dev@gmail.com` AWS account as root
- [ ] Search "Organizations" → Invitations
- [ ] You should see a pending invitation from `udeets.app@gmail.com`
- [ ] Click "Accept invitation"
- [ ] Wait ~30 sec — the existing account is now a member of the new organization

### Task 4.3: Move dev account into the dev OU

- [ ] Back in the management account
- [ ] Organizations → AWS accounts → select `udeets.dev@gmail.com`
- [ ] Actions → Move → choose `Workloads-Dev` OU → Move

### Task 4.4: (Optional) Rename dev account in the org view

- [ ] Select the account → Actions → Rename → set display name to `udeets-dev`
- [ ] (Underlying email stays `udeets.dev@gmail.com`)

### Verification

- [ ] In management account, AWS accounts list shows two accounts: management + udeets-dev (under Workloads-Dev OU)
- [ ] Billing: any charges in `udeets.dev@gmail.com` from now on will appear on the management account's bill at the next billing cycle

## Phase 5 — Create prod member account (~5 min)

Continue in management account.

### Task 5.1: Create the prod account

- [ ] AWS Organizations → AWS accounts → "Add an AWS account"
- [ ] Choose "Create an AWS account"
- [ ] AWS account name: `udeets-prod`
- [ ] Email address: `udeets.prod@gmail.com`
- [ ] IAM role name: leave default (`OrganizationAccountAccessRole`)
- [ ] Click Create — wait 1–3 min for provisioning

### Task 5.2: Move prod account into prod OU

- [ ] Select `udeets-prod` → Actions → Move → `Workloads-Prod`

### Task 5.3: Set root password and MFA on prod account

- [ ] Sign into `udeets.prod@gmail.com` Gmail
- [ ] Find AWS "Welcome" email — click the link to set a root password if needed
- [ ] Or: go to AWS sign-in page → "Forgot password" → use `udeets.prod@gmail.com` → reset and set 32+ char password
- [ ] Sign into prod account as root
- [ ] Enable MFA on root user (same as management)
- [ ] Sign out

You will not need to sign into prod as root again under normal circumstances.

## Phase 6 — IAM Identity Center setup (~30 min)

This is the most involved phase. Goal: log in once, switch between accounts in the browser.

Continue in management account.

### Task 6.1: Enable IAM Identity Center

- [ ] Search "IAM Identity Center" → open service
- [ ] Click "Enable" (if not already enabled)
- [ ] Choose AWS region: `US East (N. Virginia)` — `us-east-1` — important, must match your workload region
- [ ] Wait for it to initialize

### Task 6.2: Customize SSO start URL

- [ ] In Identity Center → Settings → Customize → "Customize AWS access portal URL"
- [ ] Set to `udeets` (full URL becomes `https://udeets.awsapps.com/start`)
- [ ] Save

### Task 6.3: Create a user

- [ ] Identity Center → Users → Add user
- [ ] Username: `udeets-admin` (or your real name)
- [ ] Email: your real personal email or `udeets.app@gmail.com`
- [ ] First name, last name
- [ ] Display name: same
- [ ] Click Next, skip group assignment for now, click Next, Add user
- [ ] Check the email — click the activation link, set a password, set MFA

### Task 6.4: Create permission sets

These define what level of access a user has when they sign into an account.

- [ ] Identity Center → Permission sets → Create permission set
- [ ] Predefined → `AdministratorAccess` → Next
- [ ] Name: `AdminAccess`
- [ ] Session duration: 8 hours
- [ ] Create
- [ ] Repeat for a second permission set:
  - Predefined → `ReadOnlyAccess`
  - Name: `ReadOnlyAccess`
  - Session duration: 8 hours

### Task 6.5: Assign user to accounts

For each member account (udeets-dev, udeets-prod):

- [ ] Identity Center → AWS accounts → select `udeets-dev` → Assign users or groups
- [ ] Pick the user you created → Next
- [ ] Pick permission set `AdminAccess` → Next → Submit
- [ ] Wait ~30 sec for provisioning
- [ ] Repeat for `udeets-prod`

### Task 6.6: Test SSO login

- [ ] Open private browser → go to `https://udeets.awsapps.com/start`
- [ ] Sign in with the Identity Center user + MFA
- [ ] You should see a list of two accounts: `udeets-dev`, `udeets-prod`
- [ ] Click `udeets-dev` → click `AdminAccess` → you're in the dev console
- [ ] Confirm you can see VPC, RDS, etc. (existing dev infrastructure)
- [ ] Go back to the portal → click `udeets-prod` → click `AdminAccess` → you're in an empty prod console

If this works, SSO is set up.

## Phase 7 — CLI setup (~10 min)

For your local machine.

### Task 7.1: Install AWS CLI v2

If not installed:
- macOS: `brew install awscli`
- Verify: `aws --version` → should say 2.x

### Task 7.2: Configure SSO profile

In terminal:

```
aws configure sso
```

Answer:
- SSO session name: `udeets`
- SSO start URL: `https://udeets.awsapps.com/start`
- SSO region: `us-east-1`
- SSO registration scopes: press Enter (default)

A browser window opens for SSO login. Sign in.

Back in terminal, AWS lists your accounts. Pick `udeets-dev` first:
- CLI default Region: `us-east-1`
- CLI default output format: `json`
- CLI profile name: `udeets-dev`

Repeat:
```
aws configure sso
```
This time pick `udeets-prod`, profile name `udeets-prod`.

### Task 7.3: Test CLI access

```
aws sts get-caller-identity --profile udeets-dev
aws sts get-caller-identity --profile udeets-prod
```

Both should return the account ID and the SSO role you're using.

If your session expires later, refresh with:
```
aws sso login --profile udeets-dev
```

### Task 8.1: Disable / delete the existing IAM user in dev

The `udeet-admin` IAM user in the dev account is no longer needed for daily access.

- [ ] Sign into dev account via SSO (Identity Center)
- [ ] IAM → Users → `udeet-admin`
- [ ] Security credentials tab → deactivate / delete all access keys
- [ ] Either delete the user, or keep it as a break-glass account with the access keys removed
- [ ] If keeping: ensure it has MFA and a strong password set, then store credentials in an offline-only location

### Task 8.2: Set up break-glass procedure for root users

Document somewhere safe (1Password shared vault):
- [ ] Management account root: email, password location, MFA device, recovery codes
- [ ] Dev account root (`udeets.dev@gmail.com`): same
- [ ] Prod account root (`udeets.prod@gmail.com`): same
- [ ] Note: root user should only be used for actions that strictly require root (account closure, billing changes, IAM identity provider changes). All daily work goes through SSO.

### Task 8.3: Delete the stale Secrets Manager secret in the dev account

- [ ] (Already scheduled — verify the secret `udeets/db/credentials` is showing "Scheduled for deletion" in the dev account)

## Notes and gotchas

- **Don't deploy anything in the management account.** It's for billing + Identity Center + Route 53 only.
- **Don't share root credentials.** Even with the team, root is for break-glass only.
- **Email handling:** AWS will send billing emails, security alerts, and password-reset emails to the root email. Check all three inboxes periodically, or set up filters to forward important messages.
- **Cost surprise prevention:** Cost Explorer in the management account will show consolidated spend across all member accounts after ~24h. Check it weekly until you have a baseline.
- **Inviting an existing account preserves everything in that account** — VPC, IAM users, resources, billing history. Only what changes is billing routes to the management account going forward.
- **Closing a member account** takes 90 days from the time you remove it from the org. Commit to this structure.

1. Recreate the Secrets Manager secret (`udeets/db/credentials`) in dev account — the management-account one is being deleted
2. Create ElastiCache (Valkey) cluster in dev account VPC
3. Create ECR repositories (`udeets-api`, `udeets-workers`) in dev account
4. Finish Cognito setup (Hosted UI domain, OAuth providers, callback URLs)
5. Create ECS Fargate cluster + ALB
6. Continue with the remaining migration plan
