# S3 Bucket and Prefix Model

Target bucket: `S3_BUCKET_NAME` (example `udeets-media`)

Optional global prefix: `S3_MEDIA_PREFIX` (example `development`, `staging`, `production`)

## Canonical key taxonomy (DB stores key only)

- `avatars/<userId>/avatar.<ext>`
- `hub-media/<ownerUserId>/<hubSlugOrId>/<kind>-<timestamp>.<ext>`
- `deet-media/<userId>/<hubSlugOrId>/deets/<timestamp>-<uuid>.<ext>`
- `deet-media/<userId>/comments/<timestamp>-<uuid>.<ext>`
- `chat-media/<userId>/<hubId>/<roomId>/<messageId>/<uuid>-<safeFileName>`

S3 object key at runtime:

- If prefix exists: `<S3_MEDIA_PREFIX>/<storage_key>`
- If prefix empty: `<storage_key>`

## Runtime URL contract

- Persist `storage_key` in DB, not full URL.
- Public render paths (`avatars`, `hub-media`, most `deet-media`) resolve as:
  - `${S3_PUBLIC_BASE_URL}/${prefixed_storage_key}` when `S3_PUBLIC_BASE_URL` is set
  - `s3://<bucket>/<prefixed_storage_key>` fallback (server/internal visibility)
- Private paths (`chat-media`) resolve through short-lived signed GET URLs.
- Uploads always use signed PUT URLs generated by API.

## Provider mode

- `MEDIA_PROVIDER=s3_primary`: S3 adapter issues signed URLs and resolves URLs from S3 key space.

## Notes

- Legacy rows that still store absolute S3 URLs are resolved at read-time.
- New media writes are normalized into key-only storage.
